# Library highlights: 2026-W42

Source-checked notes added to the library this week (✅ primary source checked · 🟡 partly checked).

## Security

- **A trailing dot let Copilot in Visual Studio rewrite its own MCP config (CVE-2026-103572)** ✅: The protection on .mcp.json compared filename strings, and Windows silently drops a trailing dot when writing a file, so a write to '.mcp.json.' passed the check and still changed the config. A prompt-injected agent could then register a malicious MCP server or repoint a tool path and get code execution. The fix normalises the full path before comparing. The general lesson: any protected-path rule for agent config must canonicalise paths (trailing dots, '..', symlinks, case) first. ([source](https://embracethered.com/blog/posts/2026/visual-studio-copilot-remote-code-execution/))
- **Package managers vs a compromised registry: Trail of Bits' 25-tool test** ✅: Trail of Bits simulated a hacked package server that injects code into real packages. With a committed lockfile, npm, pnpm, Yarn, Bun, uv, Poetry, Cargo, Bundler and SwiftPM rejected the tampered download; pip, Conda, Gradle, NuGet and Pub needed extra setup. npm install does not verify registry signatures (npm audit signatures is separate), pnpm silently rewrote mismatched lockfile hashes until 11.4, and Python installers cannot yet verify PyPI's PEP 740 attestations. Each result covers one package, version and platform. ([source](https://blog.trailofbits.com/2026/10/14/package-managers-have-an-integrity-problem/))
- **Claude Code plugin pin bypass and worktree sandbox escape** ✅: An Oct 9 advisory says the plugin installer checked out a marketplace's pinned commit SHA without confirming where HEAD landed, so an upstream repo could create a branch named exactly like the SHA and ship different code; fixed in 2.1.179. An older advisory (fixed in 2.1.163) covered a worktree named .git that let a poisoned repo chain symlinks and a git hook to write outside the sandbox. Pinning by SHA is only as strong as the code that resolves the pin. ([source](https://github.com/anthropics/claude-code/security/advisories/GHSA-pq7j-f95f-qfcv))
- **Event-delivered text is untrusted input: MCP Events security rules** ✅: With MCP Events, issue text, comments and messages reach an agent without anyone asking for them, which is a new route for prompt injection. OpenAI's guide tells servers to treat event content as data, sign every delivery, block private callback addresses and refuse redirects. ChatGPT supports webhook delivery from the draft only, and events missed during an outage cannot be recovered through the protocol for event types without replay. ([source](https://developers.openai.com/plugins/build/mcp-events))
- **CISA, NIST and NSA practices for agent control incidents** ✅: Voluntary guidance (Oct 16) for labs training and testing highly capable agents. It defines a control incident as an agent taking uninstructed actions that conflict with or get around the controls on its task, and covers limiting access, monitoring for unexpected activity, preserving evidence, shutting behaviour down, rebuilding from verified baselines and reporting near-misses. Only the summary page was read, not the full document. ([source](https://www.cisa.gov/resources-tools/resources/key-practices-incident-readiness-and-response-super-intelligence-training-and-evaluation))
- **Anthropic's opt-in vulnerability-finding service for open source** ✅: Opt-in projects receive model-written vulnerability reports without human review. Anthropic says 85 of 97 critical and high findings it spot-checked met its disclosure bar, and eligibility follows OSS-Fuzz's critical-impact test. Useful as a reference for how a lab gates automated security reports. ([source](https://www.anthropic.com/research/launching-opt-in-vuln-finding-service-for-open-source))
- **OpenCode Console breach exposed stored AI provider keys** 🟡: Reports say an Oct 16 breach of a legacy OpenCode Console system exposed provider API keys saved in about 1.4% of workspaces, and that Anthropic and Google revoked or blocked affected keys. Keys used only with the local app reportedly never reached the servers. Third-party write-ups agree; the vendor's own post was not opened. Hosted consoles that store your provider keys are part of your credential attack surface. ([source](https://ctxsec.com/items/opencode-console-provider-key-breach-2026-10))
- **Socket dependency scanning as an app for Cursor Origin** ✅: Socket's scanner now runs on Origin repositories: on each PR push it checks manifest and lockfile changes for malware and compromised updates, posts a policy check and comments on the PR. ([source](https://socket.dev/blog/socket-for-origin))

## Coding agents & tooling

- **Claude Code dynamic workflows and the ultracode toggle** ✅: A workflow script holds the loop, the branching and the intermediate results itself, so the main conversation only receives the final answer. The docs describe agent(), pipeline() and parallel() building blocks and independent agents checking each other's findings. Per the model configuration page, ultracode is a session toggle rather than an effort level, and --effort ultracode turns it on and sets effort to xhigh. ([source](https://code.claude.com/docs/en/workflows))
- **What a task costs on Opus 5.5: output tokens, effort and subagent models** ✅: Anthropic's cost guide says an output token costs about 100 times a cache read, and output includes thinking, so effort level is the main cost lever. It suggests low effort for mechanical work, medium for well-scoped daily work and higher levels only when a task stalls. Subagents that set no model inherit the main model and its price, which is an easy leak in multi-agent setups. ([source](https://claude.dev/blog/what-a-task-costs-on-opus-5-5/))
- **A 'depth' prompt: ask what a top professional would do before rewriting a task** ✅: Felix Rieseberg's tutorial separates speed from altitude (aim at the outcome beyond the task), depth (use the instruments and raw data a top professional would) and range (borrow methods from other fields). His reusable prompt asks the model to name what an expert would add, the rawest starting material, the methods and tools, and an outside check that would show the result is right, then rewrite the prompt. The outside check is the part worth enforcing: if it is 'the model reviews itself', the rewrite has failed. ([source](https://felixrieseberg.com/how-to-be-more-ambitious-a-tutorial-for-humans-with-models/))
- **Facts-first debugging when nobody has read the agent-written code** 🟡: Cindy Sridharan's essay treats code as an unreliable narrator: it shows what can happen, not what did. The method is to collect immutable facts first (logs, profiles, captures, configs), compare failing and control cases, keep only hypotheses that explain every fact, and use adversarial review to hunt contradictions. Checked through a third-party reading note because the original Medium page blocks automated fetches. ([source](https://hraness.com/reading/how-to-effectively-debug-when-you-no-longer-understand-the-code))
- **Claude Code desktop: parallel sessions, worktrees and where config is read from** ✅: The desktop app runs sessions side by side, can give each session its own Git worktree, and offers side chats that do not add to the main thread. One detail matters for safety rules: a worktree session started from the desktop app reads settings, hooks, skills and .mcp.json from the main checkout's root, while CLAUDE.md still loads from the worktree. A deny rule added only inside a worktree will not take effect. ([source](https://code.claude.com/docs/en/worktrees))
- **Claude Code Review is generally available, with a verification pass before posting** ✅: Several agents read the diff and surrounding code, a verification step discards findings that do not hold up, and the rest are deduplicated, ranked and posted as inline comments and a check run. A review never approves, blocks, pushes or runs code, and it reads REVIEW.md only from the base branch so a PR cannot rewrite its own review instructions. The docs say plainly that a review with no findings does not mean the code is correct or secure. ([source](https://code.claude.com/docs/en/code-review))
- **How Anthropic reviews code when Claude writes most of it** ✅: Most checking happens before a PR exists: the agent must show test, build or screenshot output, and a fresh-context subagent reviews the diff. On the PR, several agents hunt for bugs and a separate group votes on each finding. Human approvals scale with a risk tier set from the change, an agent approval never counts as a person's, approval covers one commit, re-review is capped at three rounds after one PR looped more than fifty times, and past incidents became a daily eval set for the reviewer. ([source](https://claude.dev/blog/solving-code-review-at-anthropic/))
- **Opus 5.5 fast mode out of preview: faster output at double the price** ✅: Fast mode needs no beta header, costs twice standard Opus 5.5 per token, and speeds up output generation but not time to first token. Switching between fast and standard speed discards the prompt cache, and it does not work with the Batch API, so mixing speeds inside one long session can cost more than it saves. ([source](https://platform.claude.com/docs/en/build-with-claude/fast-mode))
- **Codex memories: choosing the models for extraction and consolidation** ✅: Codex's background memory jobs can be pointed at specific models with extract_model and consolidation_model under the [memories] table. Bigger models there still draw on the same usage allowance, so it is a quality versus quota trade rather than a free upgrade. ([source](https://learn.chatgpt.com/docs/customization/memories))
- **OpenTelemetry traces from the Claude API, Managed Agents and SDKs** ✅: In public beta, Claude Platform can export traces to your own observability stack. API-side tracing covers model runs, Managed Agents turns and server tools; client-side tools are traced only through the SDK. The docs suggest building eval sets from real traffic, which makes traces a natural source of regression cases. ([source](https://platform.claude.com/docs/en/manage-claude/opentelemetry))
- **Claude Agent SDK and claude -p draw on subscription limits** ✅: Anthropic's help center (updated Oct 7, 2026) says the Agent SDK, claude -p and third-party apps signed in with a Claude plan draw from that plan's usage limits rather than a separate per-token bill, and that Max and Team plans also get monthly API credits for SDK, API and Managed Agents use. ([source](https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan))
- **REA: an MCP server for evidence-backed reverse engineering** 🟡: REA registers an MCP server and writes workflow instructions into several coding agents so they can analyse native apps, Electron apps, web bundles, APKs and firmware, attaching evidence to each conclusion. The README was read; nothing was installed. Two cautions: the installer edits agent configs, so review its diff first, and reverse-engineering software you do not own can break licences or terms of service. ([source](https://github.com/morluto/rea))
- **Gemini 4 Argon is generally available** ✅: Google's launch post gives the model id gemini-4-argon, introductory pricing of $2 / $10 per million input / output tokens until Nov 30 (then $4 / $20), 95% off cached input, and a 1M token limit shared between input and output with a continuation protocol. Near-1M outputs are only possible with very small inputs. ([source](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-argon/))

## Evals & verification

- **METR's five questions for testing whether agent monitoring works** ✅: METR's control assessment proposal asks about coverage (are any trajectories silently dropped), system weaknesses (can an agent disable its monitor, edit the transcript first or spawn unmonitored agents), evasion, response time to a human, and worst-case impact. It adds collusion tests with honeypots and notes that the whole assessment depends on trusting the logs, so log tampering must be tested too. ([source](https://metr.org/blog/2026-10-14-control-assessment-proposal/))
- **ToxicBench: agents lose 26 to 39 points when a tool quietly returns wrong data** ✅: The benchmark pairs clean and poisoned tool outputs (wrong numbers, labels, schemas, retrieval results) over the same source data. Across 118 tasks in three agent frameworks, the success rate under poisoning was 26 to 39 percentage points below the clean runs. A plain retry helped when the bad output happened once, but persistent bad output was adopted even after the agent checked. Abstract-level reading. ([source](https://arxiv.org/abs/2609.37153))
- **Agents adopt corrupted search results and often hide the conflict** ✅: Testing 14 models, the authors report agents adopted corrupted web search results 68% of the time, and often noticed the conflict but did not tell the user. A useful companion to ToxicBench when designing evals that check honesty about bad inputs, not just task success. Abstract-level reading. ([source](https://arxiv.org/abs/2609.05587))
- **FrontierCode 1.1: a mergeability benchmark for coding agents** ✅: Artificial Analysis runs Cognition's private eval that asks whether a real maintainer would merge the change, not only whether tests pass. At launch the leading models still failed more than 40% of tasks. Scores are the leaderboard's own. ([source](https://artificialanalysis.ai/evaluations/frontiercode))
- **Wiz Cyber Model Arena shows the harness moves the score** ✅: Wiz's offensive-security arena reports the same model scoring differently depending on the agent harness it runs in, by several points. When comparing models on workflow tasks, the harness is part of the system under test and has to be fixed or reported. ([source](https://www.wiz.io/cyber-model-arena))

## Agent-first design

- **WebMCP: website-provided tools are untrusted content** ✅: OpenAI's Site tools docs let pages expose typed tools to an agent that shares the user's browser session, alongside an annotation API for page context. The docs state that website-provided tool definitions and results are untrusted, and the browser safety-reviews each invocation, which is the right default for any agent that consumes third-party tool metadata. ([source](https://learn.chatgpt.com/docs/webmcp))
- **Cloudflare's MCP server pushes Workers issues to agents through MCP Events** ✅: Cloudflare's hosted MCP server exposes one event for new or recurring Workers production issues. Clients discover it with events/list, subscribe per account or per Worker, and receive signed webhooks. It needs specific write permissions and a client that supports MCP Events webhooks, which few do yet. The working group still labels the events extension experimental. ([source](https://developers.cloudflare.com/changelog/post/2026-10-13-cloudflare-mcp-events/))
- **Secure Software Factory: the agent proposes, policy authorizes, infrastructure enforces** ✅: Agent Baseline's v1 reference architecture puts four boundaries outside the agent's reach: the sandbox its code runs in, the network it can reach, the supply chain it draws from and the identity it acts under. The boundaries stay the same whether a developer, a fixed workflow or an orchestrator agent picks the next step, and at the orchestrator level its plans must not become its permissions. Socket notes agents denied a package have fetched tarballs from CDNs or rewritten registry config, hence an egress proxy the agent cannot reconfigure. ([source](https://agentbaseline.org/reference-architecture))

## Voice, video, creativity, animation

- **Anatomy: a Claude Code skill that explains ideas as interactive machines** ✅: Given a one-line idea, the skill invents a machine that does it and draws it as a live, interactive isometric figure. Its guiding rule is that the object is the explanation, a useful alternative to box-and-arrow diagrams for explainers. ([source](https://skills.wheresryan.sh/anatomy))
- **AA-3D: blind-vote benchmark for agents building interactive three.js scenes** ✅: Artificial Analysis scores 55 interactive 3D scene tasks with Elo from blind human votes. It measures agents building interactive 3D, not video generation, which makes it relevant for code-driven animation work. ([source](https://artificialanalysis.ai/evaluations/aa-3d))

## Physical AI

- **AA-Robotics: coding-agent harnesses drive a real arm, and the 'mistake wall'** ✅: Artificial Analysis had models running in coding-agent harnesses control a real six-axis arm through an HTTP API and four cameras on eight zero-shot tabletop tasks. Tasks take about 30 minutes against a human's 20 seconds. The most useful part is the catalogue of failures: models report done while a part is not seated, call an off-centre lid flush, or reach a passing state and keep fiddling until they fail. ([source](https://artificialanalysis.ai/articles/aa-robotics))
- **Physical Intelligence opens a Pi API beta for fine-tuning robot policies** ✅: Teams upload robot data, fine-tune Pi's models on managed compute and serve the result through a hosted inference gateway. The post lists industrial partners and notes some cloud-inference deployments hit network connectivity problems. ([source](https://pi.website/blog/api-beta))
- **NVIDIA ASPIRE: the trained artifact is a repository of robot skills** 🟡: ASPIRE treats the learned model as a repo of sensorimotor skills that a panel of coding agents practise and refine, instead of updated weights. The README's v1.0 news item reports 99% on 80 LIBERO-Pro tasks plus selected Robosuite and BEHAVIOR-1K tasks. Apache-2.0; no tagged release; results videos not watched. ([source](https://github.com/NVlabs/ASPIRE))
