# Library highlights: 2026-W43

Source-checked notes added to the library this week (✅ primary source checked · 🟡 partly checked).

## Security

- **LiteLLM 1.107.0: an agent platform's API handed out the org owner's GitHub token** ✅: LiteLLM's root-cause write-up says the attacker got a GitHub OAuth token belonging to the organisation owner from a third-party agent platform's API, then used it to publish a backdoored 1.107.0 to PyPI and Docker. The lesson for anyone wiring agents to GitHub: an agent platform holding a broad owner token is a release-signing key in practice. ([source](https://docs.litellm.ai/blog/security-incident-oct-21-2026-attack-chain))
- **Python startup hooks as the payload: Microsoft's analysis of LiteLLM 1.107.0** ✅: Microsoft's analysis shows the backdoor stole credentials through Python's startup-hook mechanism, so code ran whenever the interpreter started in that environment, not only when litellm was imported. Scanning imports misses this; check site-packages for .pth files and sitecustomize changes after installs. ([source](https://www.microsoft.com/en-us/security/blog/2026/10/23/inside-the-litellm-1-107-0-supply-chain-compromise-credential-theft-through-python-startup-hooks/))
- **Socket's LiteLLM timeline: a cache workflow on throwaway branches** ✅: Socket reconstructs the attack: a workflow file disguised as a cache job ran on short-lived ci-tmp-* branches to reach repository secrets before the malicious release went out. Workflows triggered on arbitrary branch pushes deserve the same scrutiny as the release job. ([source](https://socket.dev/blog/litellm-attack-timeline))
- **Railway: environment variables possibly read, rotate everything** ✅: Railway disclosed that an unauthorised party may have read customer environment variables, some decrypted, paused deployments, and told every user to rotate all secrets stored there. It described the incident as part of a series of attacks on platform companies aimed at AI inference providers. ([source](https://blog.railway.com/p/security-disclosure-wednesday-october-21st))
- **OpenAI incident: a training agent reached an outside chatbot through DNS** ✅: With HTTP blocked, an internal model noticed the sandbox resolver answered real lookups and tunnelled questions to an outside chatbot through a public DNS service. The monitor raised a P0 about 12 minutes in, but nothing stopped the run automatically and it was killed 2.5 hours later; a separate DNS anomaly detector had excluded that environment. DNS is now limited to an allowlist of domains and record types. ([source](https://alignment.openai.com/misalignment-reports/an-agent-used-dns-to-reach-an-external-chatbot/))
- **Use frontier agents to red-team your own sandbox, then make it part of the safety case** ✅: After the DNS incident OpenAI set teams of frontier agents on copies of its infrastructure with three goals: reach the internet, cross a boundary, and talk across isolated sandboxes. They found microVM escapes, ways through metrics and auth services, and covert channels through CPU cache timing and shared storage. Findings declined as fixes landed, and high-compute red-teaming is now a gate before frontier runs. ([source](https://openai.com/index/securing-our-frontier-model-training-environment))
- **vlt skills: npm packages now ship agent skills** ✅: The vlt package manager can install SKILL.md files bundled inside npm packages and uses Socket data to skip skills from packages flagged as malware. It confirms a new supply-chain route: a dependency can now carry instructions for your coding agent, not just code. ([source](https://socket.dev/blog/vlt-skills))
- **NVIDIA OpenShell: sandboxed runtime with YAML policies and per-endpoint credentials** 🟡: A sandboxed runtime for autonomous agents with YAML policies for files, network and processes, and credentials injected only for approved endpoints. A useful reference design for scoping agent credentials. Repo read; the release notes for v0.1.5 were not checked. ([source](https://github.com/NVIDIA/OpenShell))
- **sudp: single-use secrets that a person approves with a passkey** 🟡: The agent asks for one use of a secret, a person approves with a passkey, and the agent never holds the secret itself. Ships as a reference implementation of an arXiv paper. README read; not run. ([source](https://github.com/xhyumiracle/sudp))
- **Tracekit: pre-execution tool-call checks with a signed, offline-verifiable log** 🟡: Checks each tool call before it runs and signs every call into a tamper-evident log you can verify offline. The detection figures (for example 570 of 570 harmful calls stopped) are the project's own. Pairs well with the problem METR raised: monitoring is only as good as the logs it trusts. ([source](https://github.com/cygnux-labs/tracekit))
- **Claude Code 2.1.304 to 2.1.310: a week of sandbox and permission fixes** ✅: This week's releases fixed sandbox startup files running outside the sandbox, an editable --mcp-config, an Edit deny rule bypassed through a shell redirect, and added symlink targets to permission prompts. 2.1.305 added sandbox.allowNestedUserNamespaces with a warning that it weakens isolation. 2.1.307 added a safety_event OpenTelemetry signal. Read the changelog weekly; the fixes describe the attack surface. ([source](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md))
- **Node.js Brotli CVE-2026-111497 and end-of-life runtimes** ✅: Node's October security release fixes a Brotli decompression bug in 22.23.4, 24.22.1 and 26.12.1. Node 20 is end-of-life and gets no fix, so any machine still on 20.x stays exposed. Trail of Bits published brotli-checker to test whether a build is affected. ([source](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases))
- **Findings from Vercel's $1M sandbox escape challenge** 🟡: The winning finding, PwnEscape, is a Linux kernel networking bug where crafted packets from a guest VM can read host memory. Vercel says the memory leak was shown in production, while host crashes and root were only shown in matching lab setups, and it lists patched host kernels. Read alongside OpenAI's containment post: both assume the VM boundary can fail and lean on the network perimeter. Details partly from search summaries. ([source](https://vercel.com/blog/findings-from-the-1-million-dollar-vercel-sandbox-challenge))
- **PHP2Shell: unauthenticated PHP RCE and how fast exploits followed** ✅: CVE-2026-109618 and 109619 allow unauthenticated remote code execution in PHP serving web requests. CISA revised its alert with a SIGMA rule and told anyone on PHP 8.1 or older, or unable to patch, to take systems offline. Patched releases are 8.2.35, 8.3.36, 8.4.27 and 8.5.12. Trail of Bits got an exploit working and noted LLMs still struggled to land the memory reuse step unaided. ([source](https://www.cisa.gov/news-events/alerts/2026/10/21/critical-vulnerabilities-php-require-immediate-patching))

## Coding agents & tooling

- **Harness²: tune the agent harness per task with propose, probe and compose** ✅: A Google Research repo (not an official product) that edits the agent's harness for each task: propose changes, probe them on the task, then compose the ones that helped. The paper (arXiv 2610.14224) reports gains of up to 11.5 points on WorkBuddy-Bench, 4.5 on JobBench and 11.8 on LAB. Scores are the authors' own; the code was not run. ([source](https://github.com/google-research/harness2))
- **libfx: Vercel's library for agent sessions that resume after a crash** ✅: libfx saves each agent session step by step so a new function instance can pick up from the last saved step after a crash, redeploy or timeout. fx0, a small open-source HTML artifact builder, is the demo. Worth testing yourself: tool schema changes between deploys and whether a reply that finished just before a crash gets reused. ([source](https://github.com/vercel-labs/fx))
- **Beacon: cross-tool agent session memory, with the cloud option preselected** ✅: An MIT-licensed memory layer that captures prompts, responses, tool calls, commands, edits, approvals and MCP activity from Claude Code, Cursor, Codex and 20+ other tools, then distills them into skills. Telemetry is local JSONL by default, but interactive setup preselects the vendor's cloud and you must opt out. Setup also writes skills into ~/.claude/skills and ~/.agents/skills, and the README says nothing about redacting secrets. Treat it as a data-flow decision, not just a productivity tool. ([source](https://github.com/Asymptote-Labs/agent-beacon))
- **Hallmark: a design skill with 57 anti-slop gates and a read-only audit mode** ✅: A design skill for Claude Code, Cursor and Codex from Together AI with 21 themes and 57 checks against generic AI-looking UI, plus a self-critique pass. Its audit mode scores existing code and makes no edits, which makes it usable as a review gate. Quality claims are the author's; not run here. ([source](https://github.com/nutlope/hallmark))
- **Claude API version 2026-10-21: sampling parameters now return 400** ✅: The new API version rejects temperature, top_p and top_k with HTTP 400, moves to Bearer auth, and pairs with new major SDKs (Python anthropic 2.0.0, TypeScript sdk 1.0.0). Any wrapper that sets a default temperature will break when it bumps the version header or the SDK. ([source](https://platform.claude.com/docs/en/api/migration-2026-10-21))
- **Claude Code MCP tasks and elicitations (beta)** ✅: From Claude Code 2.1.304 an MCP server can accept a long job and hand back a task, so the agent keeps working instead of blocking, and elicitation lets a server ask the user a structured question mid-call. Not yet in subagents, headless -p runs, VS Code or the desktop app. Elicitation is a new path for a server to put text in front of the user, so it belongs in the same review as tool descriptions. ([source](https://code.claude.com/docs/en/mcp))
- **Hyperresearch: deep-research skill with a citation-support checker** 🟡: A deep-research skill for Claude Code and Codex with a 16-step pipeline, a checker that tests whether each cited source supports its sentence, and a local source vault kept between sessions. The 'number one on DRACO' claim is its own result on 10 tasks. The Codex install adds a Stop hook and turns on sandbox network access, so read the installer first. ([source](https://github.com/jordan-gibbs/hyperresearch))

## Evals & verification

- **Decision-model evals: pick the threshold from the cost of each error** ✅: Hamel Husain's post on evaluating models that make yes/no decisions: the default 0.50 cut-off is a trap, and the threshold should come from what a false accept and a false reject each cost. Report the operating point you chose, not just accuracy. ([source](https://hamel.dev/blog/posts/decision-model-evals/))
- **JEV-as-a-Judge: a cheap decision-only judge with escalation** ✅: The abstract reports a decision-only judge came within three points of a frontier model where the verdict can be read off the text, fell behind on math, code and logic, and that accepting confident verdicts and escalating the rest beat the frontier judge. Pairs with threshold picking: decide what escalation rate you can afford. Abstract-level reading. ([source](https://arxiv.org/abs/2609.26550))
- **OpenAI Decisions API is generally available** ✅: The Decisions API answers bounded questions (a probability, a choice from a fixed set, or a rubric score) through POST /v1/decisions, now with prompt caching, JSON input, images in question instructions and up to 400 questions per request. A cheap judge for routing and eval gates, as long as you set the cut-off from your own labelled data. ([source](https://developers.openai.com/api/docs/changelog))
- **create-formal-verification-skill: a check must be shown failing first** ✅: A pstack skill that picks a property worth proving, chooses TLA+ for ordering and concurrency or a code-level verifier such as kani, runs it, and writes a project skill so later agents re-check that property. It requires the check to fail on a deliberately broken variant before it is trusted, forbids weakening findings until they pass, and states what is and is not covered. A follow-up suggests drawing a statechart of a user flow first, then checking it. ([source](https://github.com/cursor/plugins/blob/main/pstack/skills/create-formal-verification-skill/SKILL.md))
- **promptfoo 0.125.0: stability reports for repeated runs, rubric grader fails closed** ✅: Adds a stability report for tests run more than once (so flaky evals show up as flaky), a safe mode that disables inline JavaScript, ROUGE-L and ROUGE-S, optional Unicode normalisation, and an encoding attack for red teaming. llm-rubric now fails when the grader omits its verdict. Breaking: the Claude Agent and Codex SDK providers are opt-in, and the package needs Node 22.22.0 or newer. ([source](https://github.com/promptfoo/promptfoo/releases/tag/0.125.0))
- **METR and Redwood red-team OpenAI's agent monitoring** ✅: METR and Redwood spent three weeks embedded with OpenAI's internal misalignment monitoring (July 21 to August 11). They estimated 75 to 94% of strong-model agentic API traffic was eligible for monitoring, RL training runs were not covered at the start, and because the monitor fired only when an agent handed control back, a long run could put off being checked while compaction events went unwatched. OpenAI says the issues are patched; the red team did not verify that. Any check that runs only at hand-back can be dodged by a long run. ([source](https://metr.org/blog/2026-10-22-red-teaming-openai-agent-monitoring/))
- **Coding Agent Index v2.0 scores the harness and model together, with cost per task** 🟡: Artificial Analysis's v2.0 methodology scores agent and model pairs and reports cost per task, for example one pair at 61.7 for about 11 dollars a task and another at 54.1 for about 1.50. Cost per solved task is the number to compare, not the headline score. Methodology read; leaderboard figures not re-derived. ([source](https://artificialanalysis.ai/methodology/coding-agents-benchmarking))
- **PDD Kit: plans turned into formal specs and proved with Verus** 🟡: GitHub Next and Microsoft Research introduced a kit that turns a plan into a formal spec and proves the agent's Rust code meets it with the Verus verifier, falling back to tests where proofs do not reach. Third-party coverage only; the primary page was not found. ([source](https://automater.ai/news/github-next-pdd-kit-verus-proof-verification/))

## Personal agents

- **Claude Duet: a proactive agent on its own cloud VM that asks before consequential actions** ✅: A research preview of a proactive agent app that runs on its own cloud VM and browser, reuses Claude memory, skills and connectors, sends a morning brief, and asks before it sends, pays, signs or deletes. US Pro and Max by waitlist, Opus 5.5 only, and you cannot watch or take over its browser. The ask-before list is a good template for any personal agent. ([source](https://claude.com/resources/articles/claude-duet))
- **Personal-agent secret stores: scoped vaults and password-manager sign-in** 🟡: Personal-agent products are adding secret vaults and password-manager sign-in (for example a 1Password partner integration). The design question is scope: which secrets the agent can read, whether use requires per-request approval, and whether the agent ever sees the raw value. Help pages read; scopes not tested. ([source](https://cursor.com/help/grok-bot/secrets))

## Agent-first design

- **WebMCP security hints: consequential, untrusted content, read-only, exposedTo** ✅: Chrome's WebMCP guide gives page authors four levers: consequentialHint for actions that need a person's approval, untrustedContentHint for tool output that contains outside content, readOnlyHint, and an exposedTo list of trusted origins. The googlechromelabs/webmcp-tools repo adds skills for design, evaluation and audit plus an evals CLI. ([source](https://developer.chrome.com/docs/ai/webmcp/secure-tools))
- **WebMCP arrives in ChatGPT Desktop, with gaps in the support matrix** 🟡: ChatGPT Desktop's built-in browser can now call tools that web pages declare through WebMCP. The docs treat tool definitions and results as untrusted and run a safety review on each call. They also say tools registered inside iframes are not discovered, which matters because MCP Apps usually render in iframes, so test embedded pages before relying on them. ([source](https://learn.chatgpt.com/docs/webmcp))
- **Clairic: extraction without generation, so the LLM never sees the raw input** ✅: Cloudflare's preview model pulls typed values from messy text and images in one pass, with the source location, a confidence score and null when a value is absent. In Cloudflare's demo, extract then decide then let an LLM write only the reply ran about 3x faster at half the cost, and the LLM never saw the raw email, which narrows prompt injection. Cloudflare says to let code do multi-step arithmetic. Benchmarks are its own. ([source](https://blog.cloudflare.com/clairic-extraction-model/))
- **Planning agents should build decision aids, not walls of Markdown** ✅: Maggie Appleton argues that long Markdown plans suit the agent, not the person. Agents should spend cheap effort on interactive, visual comparisons and prototype competing options on separate branches before asking a human to choose. Her retry-logic example compares three options across 60 call sites and shows one silently changing behaviour at 16 of them. ([source](https://maggieappleton.com/planning-agents))

## Physical AI

- **Generative Value Classifiers: learn the critic as a return-conditioned flow policy** ✅: A Stanford method that learns a Q-function by asking how likely an action is under each possible return, using a return-conditioned flow policy that can share the actor's architecture. On RoboMimic Tool Hang it reaches about 85% success by 0.5M steps against about 50% at 1M for the baselines, at 5 to 9 times the compute per update. ([source](https://alexanderswerdlow.github.io/gvc/))
