# Library highlights: 2026-W45

Source-checked notes added to the library this week (✅ primary source checked · 🟡 partly checked).

## Security

- **strutil-core: a worm that plants MCP servers and hooks, then wipes home on token revocation** ✅: A RubyGems package downloaded Bun at install time, read dozens of credential stores including AI coding tool logins, and wrote a workspace-tools MCP server and SessionStart hooks into local configs and repos. A monitor deletes the home directory if the stolen GitHub token stops working, so remove persistence before revoking. ([source](https://socket.dev/blog/shai-hulud-descendant-malicious-ruby-gem))
- **Planted files sit on branches nobody reviews** ✅: StepSecurity describes campaigns that add a .claude/settings.json SessionStart hook or a .vscode/tasks.json task with a backdated, skip-ci commit. These files aren't in any manifest or lockfile, so dependency scanners miss them; scan every branch and tag, not just main. ([source](https://www.stepsecurity.io/blog/malicious-files-find-what-supply-chain-attacks-leave-behind-in-your-github-repositories-and-on-developer-machines))
- **The tool update gap: a benign tool turns malicious on update** ✅: ETUDE ships malicious code inside an update to a tool that was safe when approved. Because the code runs outside the model's context, prompt-level defenses never see it; the attack hit 97.6% across seven frameworks including Claude Code and Codex CLI while tasks still completed. ([source](https://arxiv.org/abs/2611.01976))
- **A valid signature doesn't make an MCP tool benign** ✅: A signed MCP tool leaked data inside requests to a destination the policy allowed, and a runtime defense that blocked direct exfiltration missed it every time. The authors run each call in a data-free forked copy that only holds what that destination may see. ([source](https://arxiv.org/abs/2611.06585))
- **Destructive MCP tools usually have no approval on either side** ✅: Across a sample of the official MCP registry, about 90% of destructive tools had no server-side confirmation, and 32 of 41 popular hosts and SDKs had no approval step by default. Prompting for every tool not annotated read-only would cut unapproved pairs from 60.7% to 5.4%. ([source](https://arxiv.org/abs/2611.02527))
- **Measuring MCP tool poisoning with real execution** ✅: A 9,720-cell matrix across 12 frameworks and 18 models found 22.9% attack success, with exfiltration confirmed by a canary receiving the secret. Frameworks performed about the same, so the model decides most of the outcome, and a regex description scanner caught 20 of 45 scenarios. ([source](https://arxiv.org/abs/2611.03555))
- **mcpvenom: run tool-poisoning scenarios against your own agent** ✅: Open-source harness with 45 declarative attack scenarios, malicious and legitimate MCP servers, and canary oracles that detect a leaked secret, a tripwire read or an unauthorized action. Not officially supported by its publisher; needs a LiteLLM proxy and model access. ([source](https://github.com/dynatrace-research/mcpvenom))
- **Deterministic target checks: actions may only go where typed fields say** ✅: SPILLWAY admits a tool call only when each target value not in the user's task came from a typed field of a read-only tool. Injected instructions arrive as free text, so they can't supply a recipient or account. No templated injection redirected an action in their tests. ([source](https://arxiv.org/abs/2611.07222))
- **Capability tokens at the MCP boundary** ✅: AgentCap moves the authorization decision out of the model: each call declares an intent, a policy checks it, and approved calls get short-lived, budget-limited tokens validated at the tool. Delegated authority can only shrink. ([source](https://arxiv.org/abs/2611.00729))
- **Earn-then-exploit: coding agents trust sites that helped them before** ✅: A malicious site gives several rounds of genuinely correct help, then slips in instructions that cross a boundary. Attack success averaged 71.4% across three coding agents, higher than plain injection baselines. ([source](https://arxiv.org/abs/2611.00725))
- **apt CVE-2026-109518: packages swapped after signature checks** ✅: An on-path attacker abuses apt's resume-on-retry logic so the file installed isn't the file verified, and it runs as root. Debian 12+ and Ubuntu 22.04+ are exposed by default; fixed in apt 3.0.4 on Debian 13 and 2.6.2 on Debian 12. ([source](https://www.stepsecurity.io/blog/cve-2026-109518-apt-package-swap-root))
- **pull_request_target blocked by default on Dec 2, with brownouts first** ✅: GitHub moved the default block for public repos to December 2 and runs enforcement windows on Nov 9 and Nov 16, 16:00 to 18:00 UTC, so affected workflows fail visibly first. Private and internal repos aren't affected. ([source](https://github.blog/changelog/2026-11-02-pull_request_target-blocked-by-default-december-2/))
- **What still works against pull_request_target after GitHub's 2026 changes** ✅: Checkout protections, read-only cache tokens and event policies close the easy paths. Wiz lists what remains: explicit opt-ins, old checkout versions, unprotected triggers and script injection, with an audit checklist. ([source](https://www.wiz.io/blog/github-actions-security-pwn-request-reckoning))
- **Dependabot now updates agent skills and prompts declared in apm.yml** ✅: Dependabot opens PRs for git dependencies in Agent Package Manager files and regenerates the lockfile. It covers version updates only, not security updates, so it keeps skills current without vetting them. ([source](https://github.blog/changelog/2026-11-03-dependabot-version-updates-support-agent-package-manager))

## Coding agents & tooling

- **Upstream-sync agent rules: one upstream commit per commit, stop at the first failure** ✅: The tsrs port's sync spec has an agent port upstream commits oldest first, add a trailer with the upstream SHA, list irrelevant commits as reviewed no-ops, stop at the first conflict or failed test, and open at most one draft PR. ([source](https://github.com/oxc-project/tsrs/issues/618))
- **Codex-assisted backports landed fixes for 149 kernel CVEs** ✅: Trail of Bits uses Codex to find missing fixes, adapt patches and assemble a submission packet with test evidence; an engineer reviews and submits each one. An independent recount found most deliveries were plain cherry-picks, so the time savings skew toward easy cases. ([source](https://blog.trailofbits.com/2026/11/02/backporting-security-fixes-at-scale-with-codex/))
- **Claude Code 2.1.319: permissions.denyInsteadOfPrompting** ✅: A tool call that would wait on a permission prompt is denied and the turn continues, in terminal sessions, subagents and teammates. Useful for unattended runs where a hanging prompt is worse than a refusal. The same release fixes a worktree sandbox escape and a Bash permission bypass. ([source](https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md))
- **Codex 0.167.0: agent command center and MCP approval metadata** ✅: Adds codex agents for an overview of running sessions, includes MCP tool names and annotation hints in approval metadata, and documents managed network constraints and commands that require fresh human approval. ([source](https://github.com/openai/codex/releases/tag/rust-v0.167.0))
- **Claude message threads expire five minutes after the last request** ✅: Threads keep conversation state on the server so later requests send only new messages. Token usage stays the same because the model still reads the whole conversation, and an expired thread returns 404 so the client must resend everything. ([source](https://platform.claude.com/docs/en/build-with-claude/message-threads))

## Evals & verification

- **Ungraded episodes recorded as failures reorder leaderboards** ✅: On a public agent leaderboard, a general agent's 13-point deficit came from conversations that ended without triggering the grader, about half its episodes. The audit also found double-counted costs and grader actions logged as agent actions, each producing a plausible number with no error. ([source](https://arxiv.org/abs/2611.04399))
- **Prime Intellect's audit of public evals: fix the grader, and the scores move** ✅: Rewording tasks and relaxing unstated grader requirements changed scores drastically on several public benchmarks. Solutions republished on dataset mirrors also leak to agents with web access, and domain blocklists are the usual partial fix. ([source](https://www.primeintellect.ai/blog/auditing-public-evaluations))
- **Weight-reading claims lean on familiar datasets** ✅: Given every weight of small CNNs as text, Claude Opus 5.5 did accurate local arithmetic but named CIFAR-10 for networks trained on unrelated data and relabelled KMNIST as MNIST. Several claims built on partial tracing failed verification. ([source](https://arxiv.org/abs/2611.08070))
- **Reproducing a buzzy weight-reading result on a laptop model** ✅: Simon Willison ran the paper's own prompts against a local 27B model, which identified three of four tiny game-playing networks after long runs. A cheap replication is a fast way to size a claim before believing it. ([source](https://simonwillison.net/2026/Nov/3/qwen-can-interpret-model-weights/))
- **Random benchmark subsets are mostly fine, with a long error tail** ✅: Most random subsets estimate full-benchmark scores well, but a few are far off. BestRand keeps random sampling's cost while cutting that tail, tested on more than 70 benchmarks. ([source](https://arxiv.org/abs/2611.00883))
- **METR's assessment of AI-driven R&D acceleration at Anthropic** ✅: METR estimates roughly 2x acceleration on well-specified tasks and says redacted evidence shaped its view. Readers have to trust the assessor more than usual, which METR states itself. ([source](https://metr.org/blog/2026-11-05-anthropic-ai-rd-acceleration-assessment/))

## Personal agents

- **Dreaming: an offline pass that rewrites agent memory from transcripts** ✅: Anthropic runs a separate pass that re-reads session transcripts to correct notes and build a linked wiki. On a 25-question eval over a large document set, scaling that pass from 2 to 128 sessions raised scores from 13% to 48% of graded criteria. These are Anthropic's own evals on its own models. ([source](https://www.anthropic.com/research/components-of-agent-memory))
- **Tell strong models what memory is for instead of what to record** ✅: In Anthropic's tests, a fixed rule such as 'record only failures' wiped out much of the gain memory gave Opus 5 and Opus 4.7. When several agents wrote to one shared page, 41 of 57 contract facts survived; one agent per contract, quoting terms word for word, kept all 57. ([source](https://www.anthropic.com/research/components-of-agent-memory))
- **WASP-Mem: procedural memory as an agent-written wiki** ✅: Distils execution traces into interlinked wiki pages and raises TheAgentCompany checkpoint pass rate by 4.6 to 6.1 points with less storage. Human-defined schemas and dedup rules hurt; one round of human diagnosis of failed traces beat four rounds of self-judgment. ([source](https://arxiv.org/abs/2611.04003))
- **Memory poisoning outlives the attack: MemHarmBench** ✅: An instruction planted in one session is stored in memory, the source is removed, and a later normal task still makes decisions in the attacker's favour. Agents often finish the legitimate task with no visible anomaly, so task success alone won't reveal it. ([source](https://arxiv.org/abs/2611.01700))
- **Evidence-conditioned accuracy for memory managers** ✅: Memory managers must both update facts that changed and refuse planted ones, which call for opposite write decisions. The paper scores an answer as correct only if the records selected contain all the needed evidence, current and attack-free; existing defenses did no better than an untuned manager. ([source](https://arxiv.org/abs/2610.41056))
- **MEMOIR: gate consolidation on whether evidence survives** ✅: Compressing memory can silently destroy the evidence a later question needs. MEMOIR tests answer-relevant evidence before each merge and updates retrieval priority from which memories actually supported an answer. ([source](https://arxiv.org/abs/2611.07631))

## Agent-first design

- **json-render for Chat SDK: typed cards with readable validation errors** ✅: An agent emits a JSON spec against a component catalog and each chat platform renders it natively. Invalid specs throw one readable issue per problem for the model to fix, and a limits option rejects specs a platform would otherwise quietly downgrade. ([source](https://vercel.com/changelog/json-render-and-chat-sdk-agents))
- **Router, Workers and Watchdog: DeepSeek's super-agent prototype** ✅: One persistent Router talks to people and assigns work, Workers each run a task in their own context and directory, events become triggers, and a Watchdog restarts things. The README says parts of the design aren't implemented yet. ([source](https://github.com/deepseek-ai/dsh-superagent-prototype))

## Voice, video, creativity, animation

- **Stageshow's rehearsal gate: film the output and list what wasn't checked** ✅: A design skill that makes the agent record its own UI demo, lay frames on a contact sheet at two widths, compare against a reference and hand over notes listing what it did not check. Its own docs call the passing gate necessary, not sufficient. ([source](https://benji.org/stageshow))
- **Speculative listening for full-duplex voice models** ✅: Voice models that alternate listen and speak chunks can draft the next chunk during idle time assuming silence; the next audio didn't change output in 95.3% of chunks. The method is lossless and training-free. ([source](https://arxiv.org/abs/2611.06982))

## Physical AI

- **VABAR: open simulation benchmark for agentic robotics** ✅: Six manipulation task classes with standard variations and difficulty tiers, built on open tools and the Newton physics engine, plus a library of 33 reusable skills. A way to test LLM-written robot programs without hardware. ([source](https://arxiv.org/abs/2611.06881))
